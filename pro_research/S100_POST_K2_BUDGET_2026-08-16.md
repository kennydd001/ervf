# S100 post-K2 budget — what must still disappear

Date: 2026-08-16
Status: arithmetic synthesis from already measured results; not a new speed claim.

## Current exact anchors

Latest full V18 K=2 correctness-first oracle result supplied from the local run:

- sequential midpoint: **39.153525 ms / two target positions**;
- layer-major K2: **38.676550 ms / two positions**;
- scheduling-only gain: **0.476975 ms = 1.01233x**;
- token/state/KV/logit parity, determinism, continuation, sabotage and drift gates: PASS;
- S100 target-verifier feasibility threshold: **19.285 ms**.

Therefore the current K2 implementation must lose another:

`38.676550 - 19.285 = 19.391550 ms`

or **50.14% of the whole current K2 block**, before a real depth-1 MTP draft even gets its optimistic resident-byte allowance.

## How much can ordinary common resident projection reuse buy?

The already measured N=2 common-weight reference timings from the earlier E100/MRHS campaign cover the resident projection families that a true K2 layer-major implementation can share across positions. Using their recorded two-RHS reference pair time times calls-per-token:

| family | pair ref ms | calls | weighted ms/K2 |
|---|---:|---:|---:|
| attention Q | 0.079280 | 6 | 0.475680 |
| attention K | 0.044276 | 6 | 0.265656 |
| attention V | 0.033148 | 6 | 0.198888 |
| attention O | 0.068908 | 6 | 0.413448 |
| Mamba in | 0.149568 | 23 | 3.440064 |
| Mamba out | 0.074580 | 23 | 1.715340 |
| router | 0.025136 | 23 | 0.578128 |
| shared expert up | 0.062916 | 23 | 1.447068 |
| shared expert down | 0.064780 | 23 | 1.489940 |
| LM head | 2.149084 | 1 | 2.149084 |

The full-precision sum is **12.173296 ms per K2 block**.

Even an impossible perfect mechanism that makes *every one of those two-RHS projections cost exactly one current single-RHS read* can save at most half:

**6.086648 ms**.

Applying that impossible best case to the measured K2 block leaves:

`38.676550 - 6.086648 = 32.589902 ms`.

So **DualRHS/common projection reuse cannot by itself make native depth-1 MTP reach 100 tok/s.** It is an enabling primitive and a direct test of whether common weight traffic is reusable without the old MRHS register-pressure failure.

## Missing >=13 ms after a perfect resident DualRHS fantasy

After the theoretical perfect common-resident saving, another:

`32.589902 - 19.285 = 13.304902 ms`

still has to disappear before the 19.285-ms verifier threshold.

That additional reduction cannot come from launch scheduling: K2 already demonstrated that layer-major reordering alone is only ~0.48 ms.

The remaining high-leverage classes are therefore:

1. **Routed MoE across two positions**
   - process the union of natural routes expert-major;
   - common experts use one weight stream with two RHS;
   - cache/H2D and down-path work must be measured on the union, not estimated from route overlap;
   - sequential V18 already caches experts, so only measured incremental reuse counts.

2. **Native SM120 FP4 Tensor Core target acceleration**
   - C1 has proven lossless checkpoint weight/scale repack;
   - activation FP4 changes arithmetic and belongs to a separately gated token/quality-equivalent track;
   - activation quantization cost must be included;
   - current C2 branch tests the local hardware/API path before touching model semantics.

3. **A better temporal multiplier than native depth-1 MTP**
   - one official MTP depth caps the obvious useful multiplier around two;
   - deeper/tree proposals could raise amortization, but require a different drafter/verifier architecture rather than pretending the checkpoint exposes extra native depths.

4. **A materially faster exact target**
   - if exact single-token V18 itself falls well below 19.6 ms, every temporal scheme gets more budget;
   - gains must be integrated physical measurements, not summed component percentages.

## Claim discipline

- A DualRHS micro pass is not an S100 result.
- A native-FP4 synthetic GEMM pass is not a model-quality result.
- Native depth-1 MTP remains below its current S100 gate until an integrated target-verifier run is <19.285 ms.
- The exact V18 single-stream record remains 50.8–51.0 tok/s until a new full causal run passes the existing parity/drift gates.
