# Primary Paper Map — TreeSweep-200

This map contains primary papers and official model sources used to design the pack. Paper results are not assumed to transfer to the user hardware. Each item is used either as prior art, a required baseline, or a mechanism worth testing.

## Official target

- **[NVIDIA Nemotron 3.5 Nano model card](https://build.nvidia.com/nvidia/nemotron-3.5-nano-30b-a3b/modelcard)** — Locks hybrid architecture; does not by itself prove the user's MTP artifact.
- **[NVIDIA Nemotron Elastic 30B/23B/12B model card](https://huggingface.co/nvidia/NVIDIA-Nemotron-Labs-3-Elastic-30B-A3B-NVFP4)** — Nested-model drafter candidate; identity and runtime cost must be measured.
## Tree verification

- **[SpecInfer](https://arxiv.org/abs/2305.09781)** — Parallel target verification of token trees with exact target semantics.
## Tree optimization

- **[Sequoia](https://arxiv.org/abs/2402.12374)** — Dynamic-programming, hardware-aware tree construction.
- **[OPT-Tree](https://arxiv.org/abs/2406.17276)** — Adaptive trees maximizing expected acceptance length.
- **[DySpec](https://arxiv.org/abs/2410.11744)** — Runtime dynamic tree expansion using draft distributions.
## Tree diversity

- **[Recursive Speculative Decoding](https://arxiv.org/abs/2402.14160)** — Sampling without replacement improves tree diversity under fixed budgets.
## Verification

- **[Traversal Verification](https://arxiv.org/abs/2505.12398)** — Alternative exact verification order that may preserve useful subsequences.
## Consumer offload

- **[SpecExec](https://arxiv.org/abs/2406.02532)** — Large token trees and one-pass verification for offloaded consumer inference.
## Dynamic width

- **[Dynamic-Width Speculative Beam Decoding](https://arxiv.org/abs/2409.16560)** — Adaptive beam/tree width and multi-tree verification.
## Draft heads

- **[Medusa](https://arxiv.org/abs/2401.10774)** — Parallel independent future-token heads plus tree attention.
- **[Hydra](https://arxiv.org/abs/2402.05109)** — Sequentially dependent heads improve Medusa draft accuracy.
## Recurrent drafter

- **[ReDrafter](https://arxiv.org/abs/2403.09919)** — RNN drafter and dynamic tree attention.
## Feature drafter

- **[EAGLE](https://arxiv.org/abs/2401.15077)** — Feature-level autoregressive drafting.
## Direct-token drafter

- **[EAGLE-3](https://arxiv.org/abs/2503.01840)** — Direct token prediction and multi-layer feature fusion.
## One-pass drafter

- **[FastEagle](https://arxiv.org/abs/2509.20416)** — Non-autoregressive cascaded drafter removes sequential draft passes.
## MTP

- **[Better & Faster LLMs via Multi-token Prediction](https://arxiv.org/abs/2404.19737)** — MTP training improves model quality and can accelerate inference.
- **[FastMTP](https://arxiv.org/abs/2509.18362)** — Position-shared dependent MTP head trained for recursive drafting.
## Parallel dependence

- **[Parallel Token Prediction](https://arxiv.org/abs/2512.21323)** — Jointly predicts dependent future tokens in one call; universal representation result.
## Adaptive length

- **[SpecDec++](https://arxiv.org/abs/2405.19715)** — MDP/threshold policy for candidate length.
- **[SVIP](https://arxiv.org/abs/2411.18462)** — Training-free entropy-based draft stopping.
## Draft-free exact

- **[Lookahead Decoding](https://arxiv.org/abs/2402.02057)** — Exact parallel decoding without a separate draft model.
## Hybrid SSM

- **[STree](https://arxiv.org/abs/2505.14969)** — Packed tree scan for SSM and hybrid architectures using accumulated transitions.
- **[The Mamba in the Llama](https://arxiv.org/abs/2408.15237)** — Hardware-aware speculative decoding for Mamba/hybrid models.
## Hybrid self-speculation

- **[Component-Aware Self-Speculative Decoding](https://arxiv.org/abs/2605.01106)** — Shows hybrid composition determines self-speculation viability.
## Long context

- **[LongSpec](https://arxiv.org/abs/2502.17421)** — Constant-memory drafter and hybrid tree attention for long contexts.
- **[SparseSpec](https://arxiv.org/abs/2512.01278)** — Sparse self-speculation, delayed verification and dynamic KV management.
- **[QuantSpec](https://arxiv.org/abs/2502.10424)** — Hierarchical quantized KV/weights for long-context self-speculation.
## MoE verification

- **[MoE-Spec](https://arxiv.org/abs/2602.16052)** — Expert budgeting exposes expert-union bottleneck; lossy target branch.
## MoE tree cost

- **[EcoSpec](https://arxiv.org/abs/2607.12696)** — Adds marginal expert activation cost to draft-tree selection.
## MoE verification

- **[AcceptMoE](https://arxiv.org/abs/2608.02989)** — Commitment-weighted verifier expert sets and offload traffic reduction; changes target distribution.
## MoE hardware

- **[EdgeXpert](https://arxiv.org/abs/2608.05303)** — Depth-aware expert coalescing in speculative MoE hardware.
## Diffusion draft

- **[DEER](https://arxiv.org/abs/2512.15176)** — Diffusion drafter with acceptance lengths up to 32 on reported tasks.
## Diffusion tree

- **[D2SD](https://arxiv.org/abs/2606.04446)** — Dual diffusion draft with confidence-guided prefix tree.
- **[PRESTO](https://arxiv.org/abs/2607.22634)** — Prefix-aligned tree scoring for diffusion drafters.
## Nemotron diffusion

- **[Nemotron-TwoTower](https://arxiv.org/abs/2606.26493)** — Nemotron-based block diffusion with frozen AR context tower.
- **[Nemotron-Labs-Diffusion](https://arxiv.org/abs/2607.05722)** — Tri-mode AR/diffusion/self-speculation and diffusion-vs-MTP evidence.
## Asynchronous

- **[SwiftSpec](https://arxiv.org/abs/2506.11309)** — Disaggregated asynchronous drafting and target verification.
## Heterogeneous

- **[AHASD](https://arxiv.org/abs/2604.25326)** — Adaptive asynchronous NPU/PIM speculative execution.
- **[Dovetail](https://arxiv.org/abs/2412.18934)** — CPU/GPU heterogeneous speculative decoding.
## NPU caveat

- **[Is Your NPU Ready for LLMs?](https://arxiv.org/abs/2607.05475)** — Shows small dynamic decode workloads may underutilize NPUs.


# Roofline and exact-efficiency addendum

## Work submission and persistent execution

- **[CUDA Graph Programming Guide](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html)** — Official basis for reducing repeated launch/setup overhead; includes conditional nodes and device graph launch with fixed-topology restrictions.
- **[Mirage Persistent Kernel](https://arxiv.org/abs/2512.22219)** — Compiler/runtime megakernelization and SM-level task graphs; broad persistent-kernel prior art.

## Decode attention

- **[FlashInfer](https://arxiv.org/abs/2501.01005)** — JIT/customizable serving attention, paged KV and GQA-specific decode kernels.
- **[PersistentKV](https://arxiv.org/abs/2606.26666)** — KV-head-group mapping, page-aware work queues and long-context batch-1 scheduling.
- **[FlashAttention-3](https://arxiv.org/abs/2407.08608)** — Asynchronous producer/consumer attention pipeline and memory/computation overlap; hardware differs but mechanisms inform the kernel branch.

## Irregular fusion analogue

- **[Matrix-Free Fused Gather-GEMM-Scatter](https://arxiv.org/abs/2604.18020)** — Non-LLM evidence that eliminating gather/materialization between stages can yield large GPU speedups; used only as a mechanistic analogue.
