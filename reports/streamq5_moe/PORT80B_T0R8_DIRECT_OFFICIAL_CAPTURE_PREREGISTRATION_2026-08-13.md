# PORT80B T0-R8 direct official capture preregistration

R8 supersedes the non-executed R7/R7-R designs. It preserves their pinned official CPU backend, shard, loader, BF16/meta conversion checks, fresh-cache prefix ladder, cache schema, resource gates, raw manifests, failure evidence, real-Q5 bank prerequisite and the immutable R4 cross-backend negative.

Each layer forward directly hooks the complete official gate tuple `(native BF16 logits, selected native BF16 weights, IDs)` and its input. Manual MoE uses those directly captured IDs and weights. A diagnostic second router call must exactly equal the direct official tuple. Boundary ties are permitted and fully retained.

Before model load, each clean capture creates a unique invocation-ledger entry with PID, parent PID, OS process-create time, UTC/performance start, full command line, UUID nonce and runner hash. Capture 2 rejects identical PID/create-time/nonce. It may read capture-1 invocation metadata and the immutable bank/manifest needed for byte reconstruction, but is forbidden from reading capture-1 scientific raw/result artifacts. Only the later independent compare reads both captures.

Whole-prefix cache conv/recurrent tensors and every fresh-prefix cache are retained. Whole-prefix state must be bitwise equal to fresh prefix-16 state for each prompt.

Prompts are generated by the separately hashed deterministic generator and seed, with one declared candidate per ordered domain, no rejection and no output-dependent filtering. Capture1, capture2 and compare are separate phases. No retry or retuning. No execution is opened by this document.
