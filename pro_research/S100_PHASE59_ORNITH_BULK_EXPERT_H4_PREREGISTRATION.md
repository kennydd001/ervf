# S100 Phase59: Ornith bulk routed-expert H4 preregistration

## Question

Can the 32 worst-case unique routed-expert assignments generated by four Ornith
positions (top-8 per position) be executed as one hot, GPU-resident NVFP4 dispatch
instead of 32 serial complete-expert dispatches?

## Frozen candidate

- Checkpoint: Pottokao Ornith-1.5 NVFP4-DFlash, layer 20.
- Real routed experts 0 through 31; gate/up/down payloads are not synthesized.
- Candidate kernel maps expert/group to `blockIdx.y` and output rows to
  `blockIdx.x`; one input vector belongs to each expert assignment.
- Gate, up, SwiGLU, and down are each launched once for the full group.
- Serial control invokes the same kernels and arithmetic with group size one,
  once per assignment. This holds reduction order constant.
- Group-count curve: 1, 4, 8, 16, and 32.
- Hot/device-resident scope only. Host misses, router, recurrent state update,
  normalization, residuals, route weighting, and full decoder integration are
  outside this phase.

## Correctness gates

1. All real tensor layout contracts match NVFP4 Ornith geometry.
2. Bulk output is bit-identical to the same-kernel serial control at every group
   count and is bit-identical across repeated bulk runs.
3. Outputs are finite.
4. Experts 0 and 1 meet the independent dequantized NumPy reference gates:
   normalized RMSE <= 0.005, cosine >= 0.9999, and normalized max error <= 0.020.
5. Compiled kernels use no local memory and at most 64 registers per thread.

## Performance gate

At group count 32, bulk dispatch must be faster than serial and reach at least
2.0x speedup. Timing uses CUDA events after warm-up; the median is decisive.

## Interpretation boundary

Passing proves a hot routed-expert primitive for an H4 executor. It does not by
itself prove 65 tok/s: the measured bulk latency still has to be combined with
40 layers, shared experts, FP8 attention, routing, recurrent/full-attention
state work, cache misses, LM head, and DFlash orchestration.
